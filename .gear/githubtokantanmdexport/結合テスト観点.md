# 結合テスト観点

## テスト観点ツリー

### ITV-L1-001 API結合

#### ITV-L2-001 メッセージパッシング連携 (かんたんMarkdownデータ取得およびエクスポート機能)

- **ITV-L3-001 Content ScriptとBackground Script間のデータ送受信検証** [高]
  - content.jsからchrome.runtime.sendMessageでaction 'exportMarkdown'が送信された際、background.jsが正常に受信処理を開始すること
  - payloadに含まれるmarkdownFetchUrl、repoInfo、fileName、rawUrl、attachmentsMetadata、editionが漏れなくbackground.jsに渡されること
  - 処理完了時にsendResponseを介して{ success: true, payload: result }形式で結果がcontent.jsへ返却されること

#### ITV-L2-002 外部URL・HTMLテンプレート通信 (設定情報およびカスタムリポジトリURL管理機能)

- **ITV-L3-002 カスタムリポジトリURLに対するHEADリクエスト疎通検証** [中]
  - 入力されたcustom_repo_urlから構築したGitHub PagesのURL（https://{username}.github.io/{repo}/dist/ktm-lite.html）に対してHEADリクエストが送信されること
  - HTTPステータス200 OKが返却された場合に接続成功メッセージが表示されること
  - HTTP 404等のエラーレスポンスや通信タイムアウト時に適切な接続失敗エラーメッセージが表示されること

#### ITV-L2-003 CI/CD自動リリース連携 (Chrome拡張機能パッケージの自動ビルド・リリース機能)

- **ITV-L3-003 GitHub Actionsワークフロー起動とリリース発行検証** [高]
  - バージョンタグ（v*）のプッシュを契機にgithub-actions/release-extensionワークフローが正常に起動すること
  - GITHUB_TOKEN権限（contents: write）を用いてsoftprops/action-gh-releaseが実行されGitHub Releaseが作成されること
  - 作成されたGitHub Releaseにgithub-to-kantan-markdown.zipが正しく添付されること

#### ITV-L2-013 メッセージパッシング・ストレージ結合 (拡張機能内部メッセージ・ローカルストレージAPI)

- **ITV-L3-013 chrome.runtime.sendMessageおよびchrome.storage.local連携検証** [高]
  - content.jsから 'exportMarkdown' アクションメッセージ送信時、background.jsが要求を受信し非同期応答（sendResponse）を返却すること
  - 設定画面の保存ボタン押下時、repo_type, custom_repo_url, edition が chrome.storage.local に正常にPUT保存されること
  - オプショナルホスト権限の確認時、chrome.permissions.contains で未所有の場合に chrome.permissions.request ダイアログが起動すること

#### ITV-L2-014 外部HTTP通信・テンプレート結合 (カスタムリポジトリ接続テスト・テンプレートフェッチ)

- **ITV-L3-014 GitHub Pagesエンドポイントへのテンプレート取得および接続テスト** [高]
  - 設定されたエディション（lite/standard/full）に対応するテンプレートHTML（ktm-lite.html, ktm-std.html, ktm-full.html）が正しいURLからフェッチされること
  - 接続テストボタン押下時、構築されたGitHub Pages（https://{username}.github.io/{repo}/dist/ktm-lite.html）に対してHEAD/GETリクエストが送信され200 OKが確認できること
  - Raw Markdownデータのフェッチ失敗時（HTTPエラー）に FETCH_MD_FAILED エラー応答が正しく通知されること

#### ITV-L2-015 CI/CDワークフロー結合 (Chrome拡張機能パッケージの自動ビルド・リリース機能)

- **ITV-L3-015 GitHub Actionsリリース連携動作検証** [中]
  - バージョンタグ（v*）のプッシュ契機でワークフローが起動し、タグ名から先頭の 'v' が除去され manifest.json の version フィールドが更新されること
  - 構成ファイル（manifest.json, background.js, content.js, options.html, options.js, LICENSE, README.md）がZIPアーカイブとして正確に定義・圧縮されること
  - softprops/action-gh-release アクションを通じてリリースノートと github-to-kantan-markdown.zip が添付されたGitHub Releaseが作成されること

### ITV-L1-002 画面⇄サーバ結合

#### ITV-L2-004 DOM挿入・描画反映 (かんたんMarkdownデータ取得およびエクスポート機能)

- **ITV-L3-004 Markdownファイル閲覧画面へのエクスポートボタン動的挿入検証** [高]
  - isMarkdownPage判定によりURL末尾が '.md' のページのみエクスポートボタン（#ktm-export-btn）が挿入されること
  - MutationObserverと500msのデバウンス処理によりSPA遷移時やDOM部分更新時にもボタンが二重挿入されずに正しく配置されること
  - GitHubのアクションエリア（data-testid='raw-button'等）を検知して正しくボタンが表示されること

#### ITV-L2-005 モーダル・設定画面連携 (設定情報およびカスタムリポジトリURL管理機能)

- **ITV-L3-005 エディション選択モーダルおよび設定画面UI制御検証** [中]
  - ボタン押下時にshowEditionSelectorモーダルが表示され、デフォルトエディションが選択状態で初期化されること
  - 設定画面でrepo_typeが 'original' の場合、custom_repo_url入力欄および接続テストボタンが非活性化・クリアされること
  - 保存ボタン押下時に保存完了トーストが表示され、設定画面が正常に閉じられること

#### ITV-L2-006 入力バリデーション連携 (設定情報およびカスタムリポジトリURL管理機能)

- **ITV-L3-006 カスタムリポジトリURL形式およびタグ名の検証** [中]
  - 正規表現（^https://github.com/ユーザー名/リポジトリ名）に合致しない不正なURL入力時にエラー表示されること
  - 正当なURL形式が入力された場合のみ接続テストおよび保存処理が実行可能となること
  - manifest.jsonのバージョン書き換え時にタグ名（v*）から数字・ドット以外の不要文字列が正しく除去・正規化されること

#### ITV-L2-011 DOM挿入・描画反映 (かんたんMarkdownデータ取得およびエクスポート機能)

- **ITV-L3-011 Markdownファイル閲覧画面へのエクスポートボタン動的挿入** [高]
  - GitHubのファイルアクションエリア（data-testid='raw-button'）を検知してエクスポートボタン（#ktm-export-btn）が正しく挿入されること
  - すでにボタン（#ktm-export-btn）またはラッパー（#ktm-export-wrapper）が存在する場合に重複挿入が防止されること
  - SPA遷移および同一URL内のDOM部分更新が発生した際、MutationObserverとデバウンス（500ms）処理によりボタンが再挿入・維持されること

#### ITV-L2-012 モーダル・設定画面連携 (設定情報およびカスタムリポジトリURL管理機能)

- **ITV-L3-012 エディション選択モーダルおよび設定画面フォーム表示連動** [中]
  - エクスポートボタン押下時にエディション選択モーダル（ktm-modal-overlay）が表示され、デフォルトエディションが正しく選択されていること
  - 設定画面初期表示時に chrome.storage.local から設定値（repo_type, custom_repo_url, edition）が読み込まれてフォームに反映されること
  - リポジトリタイプが 'original' に変更された場合、カスタムリポジトリURL入力欄が無効化・クリアされること

### ITV-L1-003 DB結合

#### ITV-L2-007 ストレージ一連操作・データ整合性 (設定情報およびカスタムリポジトリURL管理機能)

- **ITV-L3-007 chrome.storage.localにおける設定値の永続化と取得検証** [高]
  - repo_type, custom_repo_url, editionの設定値がchrome.storage.localへ正しくPUT保存されること
  - 設定画面初期表示時およびexportMarkdown実行時にchrome.storage.localから設定値が正常にGET読み込みされること
  - 設定変更後もブラウザ再起動や拡張機能再読み込み時に保存された設定整合性が維持されていること

#### ITV-L2-008 テンプレート合成データ整合性 (かんたんMarkdownデータ取得およびエクスポート機能)

- **ITV-L3-008 エディション指定に応じたテンプレートHTML取得とデータ埋め込み検証** [高]
  - 選択されたedition（lite / standard / full）に応じたテンプレートHTML（ktm-lite.html / ktm-std.html / ktm-full.html）が取得されること
  - Raw Markdown本文および画像・添付ファイルメタデータ（attachments）がテンプレート内の専用DOM（<textarea id="editor">、<ul id="fileList">）に不整合なく結合されること
  - 画像等のソース参照が 'attach:cleanKey' に正しく置換され、Quine型単一HTMLとして不整合なく生成されること

### ITV-L1-004 ファイルI/F

#### ITV-L2-009 ファイル取込・フェッチ (かんたんMarkdownデータ取得およびエクスポート機能)

- **ITV-L3-009 Raw Markdownおよび画像・添付ファイルデータの個別取得検証** [高]
  - markdownFetchUrlからのRaw Markdownデータのフェッチが正常に完了すること
  - attachmentsMetadataに含まれる画像・動画等の添付ファイルURLからBlob/Base64形式データが正しくフェッチ・エンコードされること
  - フェッチ失敗時（HTTP Error）にFETCH_MD_FAILEDやFETCH_TEMPLATE_FAILEDのエラーが補足され適切なエラーメッセージが返却されること

#### ITV-L2-010 単一HTMLファイル出力およびZIPパッケージング (エクスポート処理およびCI/CD機能群)

- **ITV-L3-010 生成HTMLダウンロード処理および拡張機能ZIPアーカイブ出力検証** [高]
  - 結合されたHTMLコンテンツがBlobオブジェクトに変換され指定ファイル名（outputFileName）でブラウザからダウンロードされること
  - CI/CDワークフローにおいてmanifest.json, background.js, content.js, options.html, options.js等の必要構成ファイルが欠損なくgithub-to-kantan-markdown.zipにパッケージングされること
  - jqコマンドによるmanifest.jsonのversion書き換えがエラーなく完了すること

#### ITV-L2-016 ファイルフェッチ・単一HTML出力 (かんたんMarkdownデータ取得およびエクスポート機能)

- **ITV-L3-016 RawデータフェッチとQuine型単一HTMLファイル生成処理** [高]
  - Markdown本文内の画像URLおよび添付ファイルメタデータ（attachmentsMetadata）がBase64形式へエンコード変換されること
  - テンプレートHTML内の専用コメントタグ・タグ挿入部に対して、エスケープ処理されたMarkdown本文および添付ファイルスクリプトが正しく結合されること
  - ダウンロード実行時に、リポジトリ名やH1タイトルに基づく適切なファイル名（.html）で生成ファイルが出力保存されること
