# 業務要件一覧

| id | category | requirement | priority | description |
| --- | --- | --- | --- | --- |
| BR-001 | 設定管理 | 拡張機能の初期セットアッププロセス | 高 | ユーザーが本拡張機能をブラウザにインストールした後、最初のMarkdown変換を実行する前に、設定画面を開いて変換先となる「かんたんMarkdown」の接続先情報やエディションの初期設定を完了させる業務フロー。※要確認（初期設定が未完了の状態でエクスポートボタンが押された場合の警告表示および設定画面への誘導ルール） |
| BR-002 | 設定管理 | 接続先リポジトリの選択およびカスタム登録プロセス | 高 | ユーザーが設定画面において、オリジナルのリポジトリ（tatesuke）を使用するか、自身や組織がカスタマイズした「その他」のリポジトリを使用するかを選択し、後者の場合はリポジトリ情報を手動で入力・登録する業務フロー。※要確認（入力されたリポジトリURLが正しい形式であるかを検証・警告する業務ルールの有無） |
| BR-003 | 設定管理 | エクスポート対象エディションの選択プロセス | 高 | ユーザーが選択したリポジトリの種別（オリジナル/その他）に応じて自動生成または提示されるエディション（Lite / Standard / Full）の中から、自身の業務要件に適した出力フォーマット（エディション）を1つ選択する業務フロー。 |
| BR-004 | 設定管理 | 設定情報の保存および反映プロセス | 高 | ユーザーが設定画面で選択・入力した内容を保存し、次回以降のGitHub上のMarkdown閲覧時において、設定されたリポジトリおよびエディション情報に基づいたエクスポートが即座に実行できるよう設定値を維持する業務フロー。※要確認（ブラウザ間で設定を同期する機能要件の有無） |
| BR-005 | 設定管理 | カスタムリポジトリの公開状態（GitHub Pages）確認プロセス ※要確認 | 中 | ユーザーが「その他」のリポジトリおよびエディションを選択・保存する際、該当する「かんたんMarkdown」のHTMLファイルがGitHub Pages等で実際にホスティングされアクセス可能状態であるかを、システム的な検証を交えて確認・警告する業務フロー。※詳細未定義のため要確認（未定義：接続確認の失敗時に設定保存を制限するか、単に警告のみとするか） |
| BR-006 | GitHub UI統合・制御 | GitHub Markdown表示画面の自動検知 | 高 | ユーザーがGitHub上の公開またはプライベートリポジトリでMarkdownファイル（.mdなど）のプレビュー画面を表示した際に、ブラウザ拡張機能が対象ページであることを自動的に検知し、処理を開始する。 |
| BR-007 | GitHub UI統合・制御 | エクスポートボタンの動的配置 | 高 | 検知したMarkdownプレビュー画面の操作メニュー（Raw、Blameボタンの並びなど ※要確認）に、かんたんMarkdown形式でのダウンロードを実行するためのエクスポート用操作ボタンを動的に配置・表示する。 |
| BR-008 | GitHub UI統合・制御 | エクスポートボタン押下時のイベントハンドリング | 高 | ユーザーが配置されたエクスポートボタンをクリックした際に、現在表示されているMarkdownの本文テキストおよび関連する画像URL情報を抽出し、データ変換・ダウンロード処理のトリガーを引く。 |
| BR-009 | GitHub UI統合・制御 | プライベートリポジトリ判定とアクセス権限の引き継ぎ ※要確認 | 中 | 表示中のGitHubリポジトリがプライベートリポジトリであるかどうかを判定し、画像フェッチ処理等で必要となるブラウザセッション上のアクセス権限状態を後続処理に引き継ぐ（※プライベートリポジトリにおける詳細な認証・セキュリティ適用ルールは未定義のため要確認）。 |
| BR-010 | Markdown解析・変換 | 対象Markdownドキュメントの自動検知と抽出 | 高 | ユーザーがGitHubのリポジトリ上でMarkdownファイルを表示した際、システムが該当ファイルのコンテンツ領域を特定し、変換元となるMarkdownソーステキストを自動的に抽出する業務プロセス。※要確認：コード表示モードとプレビュー表示モードの両方に対応するかどうか。 |
| BR-011 | Markdown解析・変換 | Markdownテキストの構文解析と要素分類 | 高 | 抽出したMarkdownテキストの構文を解析し、本文テキスト、見出し構造、コードブロック、および画像リンク（タグ）等の構成要素を識別・分類する業務プロセス。 |
| BR-012 | Markdown解析・変換 | Markdown本文内の画像タグの検出・マッピング | 高 | 構文解析プロセスにおいてMarkdown内に埋め込まれている画像ファイルへのパスやURLをすべて抽出し、ダウンロード対象画像リストとしてマッピングする業務プロセス。※要確認：未定義である「ドメイン知識」に基づく非標準的な画像タグの取り扱いルール。 |
| BR-013 | Markdown解析・変換 | 画像表示タグの「Insert Tag」形式への一括置換 | 高 | 検出された画像タグの記述を、「かんたんMarkdown」でローカル添付ファイルとして画像を表示するための独自のタグ形式（Insert Tag）へ自動で置換・書き換える業務プロセス。※要確認：かんたんMarkdownのバージョンによるInsert Tag仕様の差異への対応。 |
| BR-014 | Markdown解析・変換 | エクスポート用成果物フォーマットへの自動変換・構成 | 高 | タグ置換済みのMarkdown本文と、画像制御プロセスから渡される画像添付ファイルを統合し、選択された「かんたんMarkdown」のエディション（Lite/Standard/Full）でそのまま閲覧可能なファイル構造に自動変換・構成する業務プロセス。※要確認：独自リポジトリから出力する場合の構成ルール。 |
| BR-015 | 画像データ制御 | Markdownからの画像URL抽出とデータ取得プロセス | 高 | ユーザーがエクスポート処理を実行した際、対象Markdownドキュメントから画像URLを自動抽出し、GitHubサーバーから画像データをフェッチ（ダウンロード）する業務プロセスを確立する。※要確認：対象となる画像拡張子の制限有無 |
| BR-016 | 画像データ制御 | プライベートリポジトリ画像の認証引き継ぎプロセス | 高 | プライベートリポジトリから画像をフェッチする際、ユーザーのGitHubログインセッション（Cookie等）を引き継いで自動的に認証を通し、画像データを正常に取得する。※要確認：APIトークンが必要か、ブラウザセッションの流用のみで可能か |
| BR-017 | 画像データ制御 | 画像データから「かんたんMarkdown」用添付ファイルデータへの変換プロセス | 中 | 取得した画像データを「かんたんMarkdown」に埋め込み可能なテキスト形式（Base64エンコードを想定）に変換し、添付ファイル用オブジェクトとして整理・保持する。※要確認：かんたんMarkdownがサポートするエンコード形式の技術制約およびファイルサイズ上限 |
| BR-018 | 画像データ制御 | 本文内画像タグの「Insert Tag」への自動置換プロセス | 高 | Markdown本文内のオリジナル画像タグと変換後の添付データを紐づけ、かんたんMarkdown仕様の「Insert Tag」形式に本文中のタグを自動的に置換する業務プロセスを定義する。※要確認：画像の代替テキスト（alt）の引き継ぎルール |
| BR-019 | エクスポート・ファイル出力 | エクスポート対象のデータ収集と処理起動 | 高 | ユーザーがGitHub画面上のエクスポートボタンを押下した際、表示されているMarkdownテキストとリンクされている画像データを自動収集し、変換処理を起動する。※プライベートリポジトリにおける画像アクセスのための認証ハンドリングルールについては「※要確認」。 |
| BR-020 | エクスポート・ファイル出力 | エディションに適合した成果物ファイルの生成とパッケージング | 高 | 設定画面でユーザーが選択した「かんたんMarkdown」のエディション（Lite/Standard/Full）に応じて、変換後のMarkdownドキュメントと添付画像（Insert Tag用のデータ）をパッケージングした成果物ファイルを生成する。※具体的なパッケージ形態（単一HTMLファイルへのデータ埋め込みか、ZIP圧縮等の複数ファイル同梱か）の業務上の決定プロセスは「※要確認」。 |
| BR-021 | エクスポート・ファイル出力 | 変換成果物のダウンロードとローカル保存 | 高 | 生成された成果物ファイルを、ブラウザを介してユーザーのローカル環境へダウンロード保存する。※ダウンロード時のデフォルトファイル命名規則（例：元リポジトリ名やファイル名の自動付与ルール）は「※要確認」。 |
| BR-022 | エクスポート・ファイル出力 | エクスポート結果の確認とエラーハンドリング業務 | 中 | ダウンロード完了後、ユーザーはローカルでファイルを開き、意図した形式で「かんたんMarkdown」に表示されるか検証する。変換失敗や画像の取得漏れが発生した場合の再処理プロセス、および管理者等への問い合わせフローは「未定義（※要確認）」。 |
