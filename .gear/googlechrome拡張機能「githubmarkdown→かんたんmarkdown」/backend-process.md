# バックエンド処理

| id | processName | description | input | output | relatedApi |
| --- | --- | --- | --- | --- | --- |
| BP-001 |  | ユーザーごとの拡張機能設定（リポジトリ選択区分、選択エディション、選択カスタムリポジトリ等）の保存、更新、および取得を行う。※要確認（永続化ストレージの技術要件が未定義のため、DBサーバー連携として設計） |  |  |  |
| BP-002 |  | ユーザー独自の「かんたんMarkdown」ホスティング用カスタムリポジトリの登録、更新、削除、一覧取得を処理する。 |  |  |  |
| BP-003 |  | 「その他(カスタム入力)」で登録されたリポジトリのGitHub Pages等のURLに対してバックエンドから疎通通信を行い、実際にホスティングされアクセス可能かを判定・保存する。※要確認 |  |  |  |
| BP-004 |  | プライベートリポジトリからのMarkdownデータ及び画像取得のため、ブラウザ拡張機能が持つGitHubログインセッションや認証トークンを管理・連携する。※要確認 |  |  |  |
| BP-005 |  | GitHubから抽出された生Markdownソースコードを構文解析し、埋め込まれている画像記述を抽出しつつ、かんたんMarkdown仕様の添付挿入独自タグ（Insert Tag）へ一括置換する。 |  |  |  |
| BP-006 |  | 抽出された画像URLリストに基づき、各画像をGitHubサーバーからバックグラウンドでフェッチし、Base64（Data URL）形式へ変換してバイナリ配列を構築する。※要確認 |  |  |  |
| BP-007 |  | 指定された「かんたんMarkdown」エディションのテンプレートHTMLに対し、パース・タグ置換完了したMarkdownテキストとBase64化された添付画像データを埋め込み、ダウンロード用パッケージを構成する。※要確認 |  |  |  |
| BP-008 |  | ユーザーが実行したエクスポート処理の履歴、処理対象ファイル名、適用エディション、画像処理数および成否ステータスを記録・管理する。 |  |  |  |
| BP-009 |  | システム管理者またはバッチスケジューラにより起動され、登録済みの全カスタムリポジトリの疎通状態を定期的に一括チェックし、利用不可能なリポジトリのステータスを自動で無効にする。※要確認 |  |  |  |
| BP-010 |  | エクスポート履歴（export_history, exported_images）からユーザーごとの使用頻度、合計ファイル容量、処理失敗率等のデータを集計しレポート情報として提供する。※要確認 |  |  |  |
