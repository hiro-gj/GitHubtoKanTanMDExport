# 非機能要件一覧

| id | category | requirement | targetValue | priority |
| --- | --- | --- | --- | --- |
| NFR-001 | 性能 | エクスポート処理応答時間 | 一般的なMarkdownドキュメント（画像10枚以下、テキスト50KB以下）において、エクスポートボタン押下からダウンロード開始まで3秒以内（※要確認：技術要件・技術制約未定義） | 高 |
| NFR-002 | 性能 | ブラウザ実行時のリソース消費制限 | 拡張機能動作時の一時的なメモリ増加量が50MB以下、CPU使用率ピーク時30%以下であること（※要確認：技術要件・技術制約未定義） | 中 |
| NFR-003 | 可用性 | 機能動作成功率 | GitHub Web UIの仕様変更がない通常稼働時において、エクスポート処理の成功率99%以上（※要確認：業務要件未定義） | 高 |
| NFR-004 | 可用性 | GitHub仕様変更への追随性 | GitHubのDOM構造やAPI仕様の変更に伴う動作停止時、バグ検知から5営業日以内に修正対応が可能な設計とすること（※要確認：開発体制・運用要件未定義） | 中 |
| NFR-005 | セキュリティ | 認証情報の保護 | GitHubのCookieやアクセストークン等の認証情報を拡張機能の外部サーバーに送信・保存せず、ブラウザ内セッションでのみ利用すること（※要確認：技術制約・セキュリティ基準未定義） | 高 |
| NFR-006 | セキュリティ | ローカルデータ処理の機密性 | 取得したMarkdownテキストおよび画像データを、外部の第三者サーバーにアップロードせず、すべてクライアントサイド（ブラウザ内サンドボックス）で完結して処理すること（※要確認：技術要件未定義） | 高 |
| NFR-007 | セキュリティ | 最小権限の原則に基づくパーミッション設定 | Manifest V3の仕様に基づき、拡張機能が要求するホスト権限をgithub.comおよび登録されたカスタムリポジトリURLのみに限定すること（※要確認：技術制約未定義） | 高 |
| NFR-008 | 運用 | 拡張機能のアップデート配信 | Chrome Web Store等の各ストアを通じて自動アップデート配信が行われること。配信主体やストア審査にかかる運用品質は「未定義」（※要確認：プロジェクトオーナーおよび配信運用体制未定義） | 中 |
| NFR-009 | 運用 | エラーログおよびトラブルシューティング容易性 | 画像フェッチ失敗やパースエラー等の異常発生時、開発者ツールのコンソールに解析可能なエラーコードとスタックトレースを出力すること（※要確認：技術要件未定義） | 中 |
| NFR-010 | 移行 | 既存データの移行 | 本拡張機能の新規導入に伴う、既存システムからのデータ移行要件は「未定義」（※要確認：業務要件未定義だが、クライアントサイド動作のため移行対象データは原則なしと推測） | 低 |
| NFR-011 | 移行 | バージョンアップ時の設定情報の引き継ぎ | 拡張機能の自動アップデート実行時において、ユーザーが保存したローカルストレージ内の設定情報（リポジトリ選択、エディション選択）が消失せず、シームレスに引き継がれること | 高 |
| NFR-012 | 拡張性 | カスタムリポジトリの登録拡張制限 | 設定画面に登録・保存可能なカスタムリポジトリ数を最大10件まで許容するデータ構造とすること（※要確認：業務ルール未定義） | 中 |
| NFR-013 | 拡張性 | かんたんMarkdown新エディションへの追従性 | 「かんたんMarkdown」の新しいエディションが追加された際、プログラムコードを大幅に書き換えることなく、設定定義ファイル（JSON等）の修正のみでエディション選択肢に追加可能とすること（※要確認：ドメイン知識未定義） | 中 |
| NFR-014 | 拡張性 | 複数ブラウザへの移植容易性 | Google Chrome以外のChromium系ブラウザ（Microsoft Edge等）およびFirefox等への移植が容易なよう、WebExtensions APIに準拠した共通モジュール設計とすること（※要確認：対象ブラウザおよび技術制約未定義） | 低 |
