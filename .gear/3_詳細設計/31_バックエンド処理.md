# バックエンド処理

専用バックエンドサーバーはない。本書はService Workerと周辺処理の関数仕様をまとめる。

## BP-001: DOM監視・挿入（FR-001）
content.jsのobserver/init/isMarkdownPage/injectExportButton。
documentをsubtree:true、childList:trueで監視（属性変更だけでは通知されない）。location.href変更時はlastUrl更新後すぐinit、同一URLは既存timerをclearし500ms後init。initはpathname.endsWith('.md')の場合のみ挿入関数を呼ぶ。ktm-export-btnまたはktm-export-wrapperがあればreturn。挿入先候補がない場合は何もしない。候補・UI詳細は26。

## BP-002: 実行要求準備（FR-006 / FR-002）
content.js handleExportClick / getRawMarkdownUrl / showEditionSelector。
1. ボタン元ラベルを保持しlocal.get(['language', 'edition'])、settings.edition || 'lite'でモーダル表示。言語設定（en/ja）に応じてモーダルタイトル・説明・ボタンテキストを切り替える。
2. 確定後にラベルを言語に応じて「Exporting...」 / 「エクスポート中...」、disabled=true。
3. getAttachmentsMetadataで添付を収集。
4. location.hrefの先頭GitHubホストをraw.githubusercontent.comへ、/blob/を/へ置換してrawUrlとする。
5. Rawボタンがa[href]自身ならそれを使用。そうでなければ子a[href]、祖先a[href]、ボタン自身のhrefの順で取得しlocation.origin基準で絶対化。なければrawUrlを本文取得先にする。
6. pathname.split('/')の[1]=owner、[2]=repo、[4]=branch、slice(5).join('/')=fileNameを送る（API-001）。URLデコード・ref解決はしない。
7. 応答コールバック冒頭でボタン復帰。lastErrorはalert、successならBP-007、それ以外は失敗alert（言語に応じて切り替え）。
取消・準備処理のcatchでもボタン復帰。モーダル選択値をlocalへ書き込まない。

## BP-003: DOM添付メタデータ（FR-007）
content.js getAttachmentsMetadata。最初の.markdown-bodyがなければ[]。
UUIDは16進8-4-4-4-12桁の最初の一致。名前の共通優先順は最寄りdetailsのsummary spanのtrim済text→要素titleのtrim→fallback。

| 走査順 | URLの候補順 | fallback名 | 優先度 |
| --- | --- | --- | --- |
| video | currentSrc→src→data-canonical-src→子source.src→子source.data-canonical-src | video_{outerHTML中UUIDまたはattachment}.mp4 | 1 |
| source | src→data-canonical-src | video_{outerHTML中UUIDまたはattachment}.mp4、名前共通処理は親video優先 | 2 |
| img | currentSrc→src→data-canonical-src | altまたはimage_attachment。末尾拡張子がなければ.png | 3 |
| a | a.href→href→data-canonical-src | trim済textまたはfile_attachment | 0 |

imgはUUIDとuser-attachments/assets/またはprivate-user-images.githubusercontent.com/を含むものに限定。video/source/aはUUID一致が条件で、GitHubホストに限定しない。
Mapのキーは抽出UUIDそのまま（大文字小文字を正規化しない）。既存なし・高優先度・同優先度かつhttps URLの場合に更新。後者は先のhttpsも上書きする。戻り値はpriorityを除く3項目。Worker側の一部照合では小文字化する。

## BP-004: 必須リソース取得（FR-002 / FR-011）
background.js runtime.onMessage / handleExport / clearTemplateCache / appendCacheBuster。
action==='exportMarkdown'のみ処理し、Promise結果をsendResponseへ渡す。return trueで非同期応答を保持する。未対応actionに応答を定義しない。
local.getで3キー読込→Raw本文GET→テンプレートキャッシュクリア（clearTemplateCache）→キャッシュバスター（`?t=<timestamp>`）および `{ cache: 'no-store' }` 併用によるテンプレートGETの順。repo_typeはoriginalなら安全フォールバックでfork扱い（デフォルトfork）、custom_repo_url || 'https://github.com/hiro-gj/KanTanMarkdown'、editionはpayloadEdition || settings.edition || lite。
customかつURL形式一致時は https://{owner}.github.io/{repo}（サブパスがある場合は buildTemplateCandidateUrls により候補URLリストを生成）、forkおよび未設定/original時は https://hiro-gj.github.io/KanTanMarkdown。editionが未知ならLiteファイル。
テンプレート取得前に Service Worker の Cache Storage (`caches`) 内の `ktm-*.html` エントリおよび候補URLエントリ（`ignoreSearch: true`）を削除し、各候補URLへ `?t=<Date.now()>` を付与した上で `fetch(fetchUrl, { cache: 'no-store' })` を実行することで、ブラウザおよびCDNの古いキャッシュ参照を防止する。
本文非okはHTTPステータスを含むError、本文例外は「Raw Markdownデータの取得に失敗しました: ...」。テンプレート例外は「テンプレート読み込み失敗: ...」。onMessage catchでsuccess:false/error:messageへ変換。取得先は32。

## BP-005: 画像・添付取得（FR-008）
background.js handleExport / addImageToMap / fetchImageAsBase64。
1. `/!\[([^\]]*)\]\(([^)]+)\)/g`で画像src、`/<img[^>]+src=["']([^"']+)["']/gi`でHTML画像を収集。Markdown構文木は作らない。
2. 同じsrcはimageMap内で1回。user-attachments/assets/UUIDに一致し、メタデータに同UUID（大小無視）があればそのfilenameを使用。なければsrcの末尾区間から?以降を除いたものを使用。英数・ドット・ハイフン以外を_にする。
3. http://またはhttps://で始まらないsrcはnew URL(src, rawUrl).hrefで解決。例外時はraw.githubusercontent.com/{owner}/{repo}/refs/heads/{branch}/{先頭./除去src}。
4. attachmentsMetadataも別途全件fetchし、UUID小文字のattachmentMapへ記録する。画像側との取得重複排除なし。
5. fetch成功→blob→arrayBuffer→Uint8Array。0x8000バイトずつString.fromCharCodeでbinary文字列を作りbtoa。blob.typeが空ならapplication/octet-stream。戻りはdata:{mime};base64,{data}。
6. 各失敗をcatchしsuccess=falseとconsole.warn。Promise.all後に続行。再試行・独自timeout・容量/並列数制御なし。

## BP-006: 参照変換・命名（FR-009 / FR-010）
background.js handleExport。
- 取得成功画像: `![alt](src)`→`![alt](attach:key)`、HTML imgの引用符付きsrc→attach:key。
- 取得成功メタデータ: https://github.com/user-attachments/assets/{uuid} のMarkdownリンク→[text](attach:key)、引用符付きsrc/href属性→attach:key、残る生URL→[filename](attach:key)。大小無視の順次置換。署名CDN URLなどは同じ規則で置換されるとは限らない。
- 全img開始タグからwidth/height属性を除去（引用符あり/なし対応）。取得失敗画像も対象。style等は保持。
- attachmentsへ成功かつdata:で始まる値をimageMap→attachmentMap順で格納。同keyは後勝ち。
- ファイル名は初期 `{repo}_{fileNameの末尾.md除去}.html`。Raw本文の `/^#\s+(.+)$/m` 最初の一致をtrimし、バックスラッシュ・スラッシュ・コロン・アスタリスク・?・二重引用符・<・>・縦棒・#を_にした非空タイトルがあればそれを優先。
- H1検出はコードブロックを認識しない。Windows予約名、末尾ドット、名前長、fallback中の/の完全対策はない。実際の保存名補正はブラウザにも依存。

## BP-007: HTML合成・保存（FR-010 / FR-011）
content.js downloadGeneratedFile。
1. 本文の&→&amp;、<→&lt;、>→&gt;を順に変換。
2. テンプレートの完全一致 `<textarea id="editor"></textarea>` の最初の1か所を本文入りに置換。置換は文字列引数のため$&等に置換トークン展開の制約あり（LIM-11）。
3. `/(<ul\s+id=["']fileList["'][^>]*>)([\s\S]*?)(<\/ul>)/i` 最初の一致へ追記。既存内容に大小無視でid=attach-keyがあれば追加しない。既存データ自体は更新しない。
4. keyの&/二重引用符/</>を属性向けエスケープ。Data URL中のscript閉じタグを逃がす。添付liの構造は26。非画像Editを無効化。
5. Blob(type=text/html;charset=utf-8;)→createObjectURL→一時aをbodyへ追加、download名指定、click、a除去、revokeObjectURL。ダウンロード完了自体を監視しない。
editor/fileList不一致を検出するエラーはない。Worker成功と正しいHTML出力は同義ではない。

## BP-008: 設定・疎通（FR-003 / FR-004）
options.js DOMContentLoaded。
4キー（language, repo_type, custom_repo_url, edition）をgetしフォームへ反映。初期言語はen（英語）。repo_typeはoriginal除外フォールバック（デフォルトfork）。fork時はURL欄に https://github.com/hiro-gj/KanTanMarkdown を自動入力し無効化、接続テストボタンは有効。custom時は入力有効。
言語切替: 言語ラジオ変更時に内蔵多言語辞書（en/ja）を参照し、画面全体（見出し、公式アーカイブリンク、各ラベル、ボタン、テスト結果、トースト）を即時更新。
保存: 値trim→fork時は固定URL、custom時のみ正規表現検証→local.set（language含む）→toast→1000ms後close。setのlastError確認なし。キャンセルはcloseのみ。
テスト: trim→形式検証→選択editionからURL構築（Lite: ktm-lite.html, Standard: ktm-std.html, Full: ktm-full.html）→permissions.contains(origin/*)→必要ならrequest→許可時のみHEAD。response.ok、非ok、fetch例外で多言語メッセージを出し分ける。明示timeoutなし。

.github/workflows/release-extension.yml。push.tags=v*、contents:write、ubuntu-latest、checkout@v4。

jqで作業領域のmanifest.versionを更新（commit/pushなし）。manifest.json、background.js、content.js、options.html、options.js、LICENSE、README.mdの7ファイルをgithub-to-kantan-markdown.zipへ格納。
softprops/action-gh-release@v2、GITHUB_TOKENで公開Release（draft:false、prerelease:false）へ添付。テスト実行・サンプル・.gearの同梱はない。
